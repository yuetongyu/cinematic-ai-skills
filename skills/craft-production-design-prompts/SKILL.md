# 影视概念资产文生图提示词

## 目标

先判断用户现在需要“让角色被记住”，还是“让角色可被生产复用”。英雄概念图优先保护视觉命题、轮廓、人物感情、气氛、主色和主角魅力；生产锁定再处理比例、结构、配饰、材质、皮肤、表演范围和跨图一致性。不要用生产规格提前压平第一张图的想象力。人物默认按真实演员和真人摄影处理，不按游戏数字人、3D 渲染或美容广告处理；真实不等于显老，软组织不等于赘肉，主角感不等于磨皮网红脸。人物感情可以有强烈、细腻、有魅力的形容词，但必须通过情绪对象、表演策略和身体行为落地，不能只换一张通用表情脸。

## 必读参考

- 项目包含多个资产、连续角色或统一世界观时，读取 [references/world-bible.md](references/world-bible.md)。
- 设计人物、服装、发型、面部、表情或角色三视图时，读取 [references/character-design.md](references/character-design.md)。
- 设计真人面部、头肩肖像、皮肤质感、年龄感或一页式设定板左侧特写时，读取 [references/live-action-skin-photography.md](references/live-action-skin-photography.md)。
- 设计人物感情形容词、角色专属表演气质、表情表、情绪版、情绪递进或同一角色的多种情感状态时，读取 [references/character-emotion-board.md](references/character-emotion-board.md)。
- 设计第一张英雄概念图，或需要在英雄概念与生产锁定之间切换时，读取 [references/hero-concept-pass.md](references/hero-concept-pass.md)。
- 设计地点、建筑、室内、自然环境或场景多视图时，读取 [references/environment-design.md](references/environment-design.md)。
- 设计武器、道具、工具、设备、载具、饰品或结构拆解时，读取 [references/prop-design.md](references/prop-design.md)。

只读取当前资产需要的参考。混合任务可读取多个参考，但先分别锁定每种资产，再设计它们的关系。

输入来自 `$craft-cinematic-screenplays` 时，把叙事功能、人物欲望、关系压力、场景用途和不可逆后果作为设计依据；输入来自 `$craft-world-mythology` 时，把文化母体、具体版本、证据层级、仪式/器物来源和项目改编边界作为硬约束。资产设计可以发展轮廓、结构与材质，但不能把原创混搭伪装成传统事实。

## 工作流程

### 1. 判断资产类型与交付模式

先选择模式：

- **Hero Concept Pass**：第一张角色图、主视觉、英雄概念、电影海报感、最有冲击力、没有参考图且暂不要求连续性。只保留视觉命题、3–5 个核心锚点、一个动作/气氛、一组主色和一种镜头语言。
- **Production Lock Pass**：三视图、角色设定板、表情/情绪版、服装拆解、配饰固定点、资产 DNA、跨画面一致性、剧组交接或已有英雄概念的生产化。此时才加载完整的结构、材质、皮肤、表演范围、左右和负面控制。

用户只说“设计一个角色”时，默认 Hero Concept Pass；用户明确要求三视图、资产锁定或生产参考时，才使用 Production Lock Pass。

先判断资产类型：

- 角色：身份、身体、面部、服装、发型、表情和行为习惯。
- 场景：地点功能、空间结构、建筑系统、环境状态和生活痕迹。
- 物品：功能、结构、尺度、材质、使用方式和磨损历史。
- 世界观：让多个角色、场景和物品共享同一设计逻辑。
- 混合资产：角色与坐骑、人物与机械外骨骼、建筑与载具等不可分割组合。

再选择交付模式：

1. **主概念图**：确定资产核心形象和设计命题。
2. **设定参考图**：稳定展示形体、比例、材质和结构。
3. **独立多视图/三视图**：正面、侧面、背面、四分之三视角分别锁定。
4. **一页式角色三视图设定板**：左侧 1/3 为大型头肩或上半身面部特写，右侧 2/3 为同一角色的 Front、Profile、Back 全身视图，并严格对齐比例。
5. **角色感情词典 / 情绪版**：为同一角色建立故事需要的感情形容词、表演基线、受控情绪状态和独立提示词；不套固定喜怒哀乐。
6. **变化方案**：在保持 DNA 的前提下变化服装、年代、损坏、天气或用途。
7. **英雄展示图**：用克制的镜头与光线表现资产魅力，但仍保证设计可读。
8. **电影镜头交接**：把锁定后的资产交给 `$craft-cinematic-image-prompts` 进入剧情、机位、布光、动作和特效设计。

Hero Concept Pass 默认只输出视觉命题、3–5 个核心锚点、一张英雄概念图提示词、短负面词和一段 `HERO CONCEPT HANDOFF`；不要自动输出配饰登记表、尺寸、左右固定点、三视图比例或长篇生产负面。

Production Lock Pass 才输出主参考图/设定图、完整资产 DNA、配饰登记表、皮肤与年龄锁定、角色需要的感情词典/情绪版、负面提示词、一致性锁定和必要的多视图。不要自动生成拥挤的九宫格；用户未要求情绪版时也不要机械附赠通用表情表。

### 2. 确定设计命题

先用一句话回答：

`这个资产在世界中做什么，它的外形必须让观众立即相信什么。`

Hero Concept Pass 还必须写一句“视觉命题”，把角色的魅力、危险、反差或奇观压缩成一个可被画面证明的核心。例如：`轻盈柔媚的外表承载紫色、危险、流动的毒性`。如果一句话无法统领元素，先删减元素，不要继续堆标签。

再确定：

- 叙事功能：它如何帮助、限制、保护、威胁或暴露人物。
- 身份信息：时代、地域、阶层、职业、组织、文化或技术来源。
- 核心矛盾：先进但粗陋、威严但衰败、轻盈但危险、神圣但被工业化等。
- 识别优先级：第一眼轮廓、第二眼结构、最后发现的细节。
- 角色层级：主角、重要配角、功能角色或群像成员；主角必须拥有可重复的选角辨识度、眼神意图、姿态控制和轮廓锚点。

设计意义必须编码在轮廓、比例、材料、结构和使用痕迹中，不依赖说明文字或无关象征物。

### 3. 建立资产 DNA

把特征分为三层：

- **不可变特征**：跨视角和跨画面必须保持，例如脸部骨相、体型比例、建筑主轮廓、道具核心结构和标志性缺口。
- **受控特征**：可以变化但必须遵循范围，例如人物表情/情绪强度、发型整理程度、服装外层、天气、损坏级别、场景陈设和表面污渍。
- **自由特征**：不影响身份识别的小细节，例如次要配件位置、轻微褶皱、微小划痕和背景杂物。

Hero Concept Pass 只保留 3–5 个核心锚点；Production Lock Pass 最多保留 5–7 个真正可识别的不可变 DNA 锚点。不要把几十个细节都声明为不可变，否则模型难以执行。

人类角色另外锁定“感知年龄目标”，通常与设定年龄保持在约 ±3 岁的可见范围；写清允许出现的静态纹、眼下状态、面颊支撑、下颌与颈部状态，以及禁止增加的老化特征。不要用深皱纹、眼袋、法令纹、面颊下垂、赘肉或颈纹作为“真实感”的默认快捷方式。

角色存在配饰时，另外建立“配饰登记表”。逐件锁定规范名称、数量、相对尺寸、材质、颜色、身体固定点、解剖学左右、穿戴层级、朝向、垂坠/受力方式、磨损状态和各视角可见性。标志性配饰属于不可变 DNA；纯装饰性小件才能进入受控或自由特征。

人类角色需要情绪版时，另外锁定“情绪基线与表演签名”：角色平时如何控制感情、眼神习惯指向哪里、哪个身体部位最先泄露、面对权威/亲近者/威胁时倾向靠近还是撤退，以及允许的表演强度。具体情绪是受控变量；骨相、年龄、软组织、永久皮肤标志、发型、服装和配饰仍是不可变身份。

### 4. 建立结构、功能与材质逻辑

Hero Concept Pass 只写能改变轮廓、动作、材质观感或世界观气质的结构；不要在第一张图里解决每个扣具、固定点、尺寸和装配逻辑。Production Lock Pass 才逐项解释功能、受力、连接和制造逻辑。

让结构回应功能：

- 人物身体、服装、配饰和装备必须支持其职业、年龄、动作和生活环境；每件配饰必须有可信的穿戴、扣合、穿孔、绑扎、夹持或承重方式。
- 场景尺度、入口、通道、楼层、承重、排水、通风和使用区域必须可信。
- 物品的握持点、受力点、连接件、开合、能源、维护和损坏方式必须可解释。

让材质回应制造与使用：写明材料、表面处理、连接方式、受力磨损、环境腐蚀、清洁程度和维修痕迹。磨损必须出现在高接触、高摩擦、暴露或受力区域，不能平均撒满表面。

### 5. 选择正确的展示系统

#### 设定参考图

使用中性、稳定、低歧义的展示：

- 接近正交或自然中长焦透视。
- 眼平或与资产中心平齐的机位。
- 均匀柔和的中性光，清楚显示颜色和材质。
- 简洁背景、中等景深、完整轮廓和合理接触阴影。
- 不使用戏剧化广角、极浅景深、强烈烟雾、粒子、炫光或遮挡。

#### 真人角色摄影

人物面部默认使用真实演员摄影语言。用自然中长焦、正常肖像工作距离、中等景深、有方向的柔和主光和克制负补光建立软组织体积。明确额头/鼻部的局部皮脂微光、面颊与下颌的较哑光区域、眼睑与唇部的有限湿润反光；不要让整张脸统一油亮。

将修图限制为临时干扰的局部清理。保留痣、雀斑、晒斑、浅疤、痘印、眼下结构、表情纹、毛孔区域差异、细绒毛、毛细血管、局部泛红、肤色冷暖变化和轻微左右不对称。不要默认磨皮、美白、瘦脸、祛眼袋、祛痣、锐化虹膜或漂白眼白/牙齿。

先锁定角色的实际年龄、感知年龄和当前健康/疲劳状态。年轻或壮年角色的真实肉感来自皮肤弹性、稳定脂肪垫、健康含水量、面颊连续体积和自然下颌过渡，不来自松弛、赘肉、双下巴、深法令纹或重眼袋。只有设定、年龄、体脂或剧情明确要求时才增加这些特征。

角色为主角时，加入真实电影选角意义上的 `lead-performer screen presence`：面孔具有一至三个鲜明但可信的识别锚点，眼神清醒并指向明确目标，头颈关系舒展，身体重心稳定，发型与服装轮廓经过控制，面部得到最清楚但非美容化的光线。主角感来自叙事控制力和视觉优先级，不来自完美对称、削尖下颌或无瑕皮肤。

#### 角色感情词典 / 情绪版

先从人物欲望、关系、创伤、职业和控制方式提炼角色专属的感情词典，不为所有人套同一组喜怒哀乐。每个状态使用“一个主情绪形容词短语 + 一个反向次情绪 + 一个具体对象/触发”，例如 `guarded tenderness complicated by distrust`。例子只展示精确度，不得固定复用。

每个情绪状态建立 `EMOTION PERFORMANCE CARD`，至少写清：对象与触发、公开/私下/伪装、强度 1–5、行动倾向、眼神与眼睑、嘴唇/下颌/吞咽、呼吸、头颈/肩部/重心、手部与道具接触、允许变化和绝对不可变化。形容词负责统一表演，身体证据负责让模型看见感情。

质量优先时，每种情绪输出独立头肩提示词，保持相同演员身份、头部尺度、机位、自然中长焦观感、工作距离、景深、背景、发型、服装、配饰和基础光线。用户明确要求一页式情绪板时，才在横向画布中设置 4–8 个等尺寸头肩格；首格可为中性身份基线，其余状态必须由当前故事推导，文字标签留给后期。

生产三视图默认保持中性或低强度可比对状态，情绪板另做。不要把哭泣、咆哮、夸张低头或动态手势混入 Front/Profile/Back，导致比例、配饰和脸部身份无法校验。完整方法读取 [references/character-emotion-board.md](references/character-emotion-board.md)。

#### 多视图

优先为每个视角输出独立提示词，再用同一资产 DNA、比例、材质和光线生成。只有用户明确需要排版稿时，才提供多视图联系表提示词。

用户要求“一页式三视图”“左侧面部特写 + 右侧 Front/Profile/Back”或同类排版时，使用 [references/character-design.md](references/character-design.md) 中的固定角色设定板布局。此时允许在一张横向画布中重复展示同一个角色四次，但必须明确它们是同一人的面部特写和三个观察角度，而不是四名不同人物。

不要依赖生成模型准确书写标签、尺寸或说明文字；把文字标注留给后期排版。

#### 英雄展示图 / Hero Concept Pass

允许使用强烈的三分之四视角、低机位、环境光、毒雾、风、薄纱、火花或其他能统一视觉命题的气氛。此模式优先保证第一眼冲击力、轮廓、主色、动作和情绪，不强行采用中性设定光、不展开配饰登记、不用规格表打断画面。英雄图不是最终剧情镜头，也不是生产三视图。

### 6. 组装提示词

Hero Concept Pass 按以下顺序写正向提示词：

1. 一句视觉命题、角色层级、主角魅力与人物感情气质
2. 3–5 个核心轮廓/身份锚点
3. 情绪对象、表演策略和一个决定性动作或气氛事件
4. 主导色、支撑色和强调色
5. 一种镜头语言、布光和空间关系
6. 少量材质/世界观语汇
7. 简短的真人摄影可信度

Production Lock Pass 才按以下顺序写完整提示词：

1. 资产类别、角色层级、叙事功能和设计命题
2. 不可变 DNA、感知年龄目标、情绪基线/表演签名与主要轮廓
3. 比例、结构、功能和空间关系
4. 材质、工艺、颜色和磨损
5. 当前视角、情绪对象、主/次情绪、可见表演、姿态或环境状态
6. 展示镜头、背景、光线和景深
7. 超写实影视概念设计质感与输出用途

使用可见名词和结构性动词。Hero Concept Pass 允许使用经过画面证明的 `seductive`、`alluring`、`dangerously elegant`、`striking`、`glamorous but ominous`、`sensual silhouette` 等审美词；不要用抽象安全词把魅力抹平。避免 `masterpiece`、`best quality`、`8k`、`highly detailed` 等质量词堆叠。

允许使用 `contained grief`、`restrained fury`、`fragile hope`、`dangerously amused`、`seductive self-possession` 等有角色感的情绪形容词，但必须紧接情绪对象、隐藏策略与眼神/呼吸/手部/姿态证据。不要堆 `sad, sorrowful, melancholic` 等近义词，也不要只靠泪水、颜色或烟雾表示情绪。

人物提示词默认以 `photographed live-action human subject`、`live-action casting and wardrobe reference photograph` 或同类真人摄影描述开头。不要只写 `hyperrealistic character concept art`、`digital human`、`PBR skin`、`3D render` 或 `ultra-detailed pores`；这些表达容易制造游戏 CG、程序化皮肤和毛孔贴图感。

### 7. 生成定制负面提示词

Hero Concept Pass 只用 8–15 个真正破坏画面的负面词，例如游戏 CG、普通时装目录、元素拼盘、平光、空洞视线、静态证件照姿势、塑料皮肤、签名道具不可读、文字和水印。Production Lock Pass 才根据资产类型排除：

年龄相关负面词必须服从设定年龄和参考图。只排除“超过年龄锁定”的皱纹、眼袋、下垂与赘肉；老年、特殊体脂、疾病或明确妆效角色不得机械禁用其有效身份特征。

- 身份漂移：年龄变化、脸型变化、体型变化、发色变化、服装重设计、标志缺失。
- 年龄膨胀：比设定明显更老、年龄不相符的深皱纹/重眼袋/法令沟、面颊下垂、嘴角下垂、赘肉、双下巴、松弛颈部或疲劳状态被误解为永久衰老。
- 主角层级错误：空洞视线、畏缩或瘫软姿态、无辨识度平均脸、被背景吞没、关键面孔曝光不足，以及配角比主角更亮、更锐、更大或更具色彩优势。
- 情绪与表演错误：无对象的通用喜怒哀乐脸、表情包式五官、舞台式怪相、无因流泪、默认尖叫/张嘴恐惧、默认咆哮式愤怒、撅嘴式魅惑、所有情绪版本共享同一表情、情绪导致换脸或年龄漂移。
- 真人质感错误：游戏 CG 脸、数字人、蜡像、塑料皮肤、玻璃肌、全脸油光、均匀毛孔、磨皮、美白、程序化纹理、美容广告光、HDR 脸和过度锐化。
- 配饰漂移：配饰增减、换边、镜像、尺寸变化、材质变化、固定点移动、层级互换或在不同视图中无故消失。
- 结构错误：多余肢体、错误关节、悬浮部件、无连接结构、比例矛盾、不可用入口或握把。
- 视图错误：透视夸张、不同视角混合、裁切关键结构、镜像不一致、左右特征互换。
- 材质错误：塑料感、材质混合、均匀磨损、错误反射、无接触阴影。
- 画面干扰：复杂背景、强烈特效、烟雾遮挡、海报构图、文字、水印、签名和边框。

### 8. 维持跨图一致性

Production Lock Pass 每次重复生成时锁定：

- 世界观版本与时代。
- 资产名称和不可变 DNA。
- 身体/建筑/物品比例。
- 材料、颜色、标志、损坏和左右方向。
- 角色配饰的数量、名称、身体固定点、左右、层级、朝向、相对尺寸、材质和状态。
- 人物皮肤的年龄状态、永久标志、肤色底调、区域纹理、局部光泽和当前健康/环境状态。
- 人物的设定年龄、感知年龄范围、允许的年龄特征、禁止的年龄膨胀特征和主角选角锚点。
- 人物的情绪基线、表演签名、当前情绪对象、允许变化的表情/姿态字段，以及不得因情绪改变的身份字段。
- 相机视角类别、光线性质和背景用途。

只改变用户要求变化的字段。不要为了“更有创意”擅自改动身份锚点。

如果平台支持种子、参考图、角色参考、结构控制、姿态控制或局部重绘，建议先生成主参考图并锁定，再扩展其他视角。不要虚构平台参数。

### 9. 交接到电影镜头

用户需要最终剧情图时，先输出一个“电影镜头交接块”：

```text
资产名称：
不可变外观：
可变化状态：
材质与颜色：
人物配饰及固定位置：
真人皮肤、年龄与永久标志：
感知年龄与禁止老化特征：
主角选角感与视觉锚点：
情绪基线与表演签名：
当前主情绪 / 反向次情绪：
情绪对象、隐藏策略与行动倾向：
尺度与空间关系：
功能与动作限制：
当前损坏/天气/年代状态：
```

将交接块与剧情要求一起交给 `$craft-cinematic-image-prompts`。电影镜头可以改变机位、布光、动作和气氛，但不得破坏不可变资产 DNA。

### 10. 做终检

提交前检查：

- 第一眼能否识别资产类别、身份和核心轮廓？
- 设计是否由功能、文化、环境和历史共同产生？
- 是否存在 5–9 个清晰且可重复的 DNA 锚点？
- 多视图的年龄、比例、左右方向、结构和材质是否一致？
- 角色配饰是否数量一致、位置一致、左右不变，并通过带、扣、链、针、夹、穿孔或支架真实连接身体/服装？
- 被身体遮挡的配饰是否只是不可见，而不是被重新设计或错误移除？
- 一页式三视图中，Front、Profile、Back 是否同头高、同脚底基线、同头身比和同服装状态？
- 左侧面部特写是否与右侧三视图属于完全同一身份，且没有侵占右侧全身展示区域？
- 人脸是否先具有骨骼、脂肪垫、肌肉、眼睑和下颌软组织体积，而不是在光滑模型上贴毛孔？
- 软组织是否表现为年龄相符的弹性、支撑和健康体积，而不是被误写成面颊下垂、赘肉、双下巴或松弛颈部？
- 人物的感知年龄是否与设定年龄接近，且疲劳、伤病和生活痕迹没有无故增加十岁？
- 主角是否通过眼神目标、头颈姿态、轮廓、服装、焦点和光线形成第一视觉层级，而不是靠美容脸或夸张英雄姿势？
- 情绪形容词是否精确指向人物关系，并由眼神、呼吸、下颌、头颈、手部和行动倾向证明？
- 主情绪与反向次情绪是否形成角色张力，而不是近义词堆叠？
- 情绪版本是否保持同一脸、年龄、健康软组织、永久皮肤标志、发型、服装、配饰和摄影基线？
- 悲伤、愤怒、恐惧、疲惫或魅惑是否被错误地表现为突然老化、脸部变形、空洞瞪眼、全脸油亮或美容磨皮？
- 情绪表是否来自当前故事需要，而不是固定输出喜怒哀乐套餐？
- 皮肤是否按额头、鼻部、眼周、面颊、口周和下颌呈现不同纹理、色差和光泽？
- 是否保留年龄、痣、斑、浅疤、眼下结构、细毛和轻微不对称？
- 是否避免美容正面光、环灯眼神光、全脸均匀反光、磨皮、美白、HDR、过度锐化和游戏数字人质感？
- 参考图是否因电影化光线、浅景深或特效而失去可读性？
- 磨损、污渍和损坏是否出现在合理区域？
- 是否能说明每个主要结构的用途或制造逻辑？
- 负面提示词是否针对本资产最可能发生的漂移？
- 电影镜头交接是否清楚区分不可变与可变化特征？

发现问题时直接修正。

## 默认输出格式

### 任务判断

说明资产类型、交付模式（Hero Concept Pass 或 Production Lock Pass）和需要补全的关键假设。

### 设计命题

用 2–4 条中文短句说明叙事功能、世界观归属、核心矛盾和识别顺序。

Hero Concept Pass 额外用一句话写视觉命题，不展开生产规格。

### 英雄概念图方案

Hero Concept Pass 输出：视觉命题、3–5 个核心锚点、动作/气氛、主色、镜头语言、英文主提示词、短负面词和 `HERO CONCEPT HANDOFF`。Production Lock Pass 不输出本节，除非用户要求回到主视觉探索。

### 资产 DNA

Production Lock Pass 才分别列出不可变特征、受控特征和自由特征；Hero Concept Pass 只列 3–5 个核心锚点。

### 角色配饰锁定

Production Lock Pass 且用户需要连续性时，才逐件列出：规范名称、数量、相对尺寸、材质/颜色、解剖学左右、固定位置、穿戴层级、朝向、运动方式、磨损和各视角可见性。Hero Concept Pass 只写会改变主轮廓或视觉命题的标志性配饰。

### 真人摄影与低修图方案

Production Lock Pass 设计人类角色时，说明设定年龄与感知年龄目标、允许/禁止的年龄特征、健康软组织状态、主角选角锚点，以及面部/全身使用的焦段观感、景深、主光方向、负补光、局部皮肤光泽、需要保留的身份纹理和允许修复的临时干扰。Hero Concept Pass 只保留一到两句真人摄影可信度，不输出完整低修图清单。非人角色不输出本节。

### 角色感情词典与情绪版提示词

仅在用户要求人物感情、表演气质、表情表、情绪版、情绪递进或同一角色的多种状态时输出。先给出角色的情绪基线/表演签名，再从当前故事提炼 4–8 个有用状态；每个状态提供主情绪形容词、反向次情绪、对象与触发、公开/隐藏策略、强度、行动倾向、可见表演、不可变身份和独立英文提示词。除非用户明确要求联系表，默认逐张生成，不做拥挤九宫格。

### 主提示词

输出可直接复制的英文正向提示词。一个提示词默认只描述一个资产和一个视角。

### 中文对照

给出忠实的中文设计描述，便于审阅身份、结构和材料。

### 补充视图提示词

仅在用户要求三视图、变化稿、结构图或多状态时输出。不同视图使用独立提示词，并重复必要的资产 DNA。表情/情绪版优先使用上一节的专用格式，不把它当普通视图随意附加。

用户明确要求一页式角色三视图设定板时，改为输出一个完整的横向排版提示词和一段布局专用负面提示词，不再拆成三个独立视角提示词；同时提醒准确的 `Front`、`Profile`、`Back` 文字可在后期排版中校正。

### 负面提示词

输出与当前资产和视图匹配的英文负面提示词。

### 一致性锁定

Production Lock Pass 给出后续生成必须重复使用的简短锁定块，以及平台中立的一致性建议。Hero Concept Pass 输出 `HERO CONCEPT HANDOFF`，不把未验证的细节伪装成硬约束。

### 电影镜头交接

仅在用户准备把资产放入剧情画面时输出。

## 平台适配

- 平台未知：输出自然语言正向提示词、负面提示词和独立视图/情绪提示词。
- Flux：使用连贯自然语言，明确空间、结构和身份关系，减少标签与复杂权重。
- ComfyUI / SDXL：可分为资产 DNA、结构、材质、视图和展示环境；将负面提示词单独输出。
- Midjourney：压缩重复语句，但保留不可变 DNA；多视图优先逐张生成。
- 不支持负面提示词的平台：把最重要的排除项改成正向限制，并将完整负面词作为人工检查清单。
- 用户若要求实际生成图片，在完成提示词后调用可用的图像生成能力；用户只要提示词时不要擅自生成图片。
