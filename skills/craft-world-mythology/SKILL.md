# 世界神话编剧与研究

## 核心定位

把神话当作一套关于秩序、生命、死亡、祖先、自然、权力和越界的文化系统，而不是可随意抽取的名字、怪物和武器清单。使用本 skill 时，先检索源数据，再按需要进行网络核验，最后把结论转化为可写、可拍、可持续开发的戏剧结构。

skill 内置的默认数据源是 `references/world-mythology-dataset.md`，它是用户提供的 Markdown 外壳 JSON 数据集。不要把它复制进提示词或一次性全部读入上下文；使用 `scripts/query_mythology.py` 做定向检索。源数据可通过 `--source PATH` 或 `MYTHOLOGY_SOURCE` 替换，读取时以实际指定文件为准。

## 工作模式

先判断用户要的是哪一种输出，再选择最小必要检索范围：

1. **事实检索**：查实体、别名、体系、关系、故事背景、能力、住所、武器、术法和来源。
2. **谱系研究**：比较两个或多个传统的宇宙秩序、传承媒介、代理人关系、边界技术和历史层次。
3. **影视改编**：把一条神话关系或事件转成角色欲望、因果压力、场景转折、视觉动作、代价和长线悬念。
4. **神话资产开发**：为神祇、英雄、异兽、神器、祭仪、圣地和世界规则建立可连续生产的 DNA。
5. **事实审查**：识别数据集中的版本混合、后世改写、疑似模板、争议叙述和不应当直接当作史实的内容。

涉及剧本结构时，继续使用 `$craft-cinematic-screenplays`；涉及电影级生图或资产提示词时，继续使用 `$craft-cinematic-image-prompts` 或 `$craft-production-design-prompts`。本 skill 提供神话研究与改编逻辑，不替代这两个技能的摄影、表演和提示词流程。

## 数据检索

先运行查询脚本，不要手工翻阅三万行 JSON。以下命令从 skill 根目录执行；从其他目录运行时把脚本路径改成该 skill 的实际安装路径：

```bash
python3 scripts/query_mythology.py stats
python3 scripts/query_mythology.py systems
python3 scripts/query_mythology.py validate
python3 scripts/query_mythology.py entity "后羿"
python3 scripts/query_mythology.py search "四目" --system "中国上古神话"
python3 scripts/query_mythology.py relations "黄帝"
python3 scripts/query_mythology.py spells "占卜"
```

需要机器处理时加 `--json`；需要更多结果时加 `--limit N`；需要限制体系时加 `--system "体系名"`。源文件路径变化时用 `--source /path/to/file.md`，不要修改脚本中的默认路径。

定向检索规则：

- 先用 `systems` 确认体系名称，再用 `entity` 或 `search` 查实体；不要把同名人物自动合并。
- 查事件时优先看实体的 `relations[].event`，再看 `story_background` 与 `detailed_description`；关系类型不能代替事件本身。
- 查武器、法宝和术法时同时读取 `weapons`、`spells`，记录它们属于谁、从何而来、能做什么以及使用限制。
- 需要完整上下文时只读取命中的实体，不要把 597 个实体全部展开给用户。
- 数据集里的 `sources` 是线索，不等于已经核验的原典。对具体引文、年代、版本、活态宗教和争议事实进行网络检索，并优先使用原典、博物馆、大学、学术出版物或传统内部的权威来源。

## 证据分层

每次研究或改编都明确标注以下层级，不能混写：

- **数据集记录**：来自用户文件的字段或关系，标记为“数据集记载”。
- **原典/一手来源**：古典文本、碑铭、仪式记录、博物馆藏品说明、传统内部的权威材料。
- **学术解释**：学者对版本、地域、年代和传播的解释；说明不确定性。
- **民间/后世流行版本**：小说、影视、游戏、网络叙事或现代重构；不能倒写成古代原貌。
- **本项目改编**：为角色、冲突、镜头或世界规则新增的内容，显式写成“项目改编”，不要伪装成神话原文。

网络检索时，若用户要求精确资料、链接或当前研究，必须浏览。技术和史料问题优先引用一手或学术来源；不同来源冲突时并列版本、解释冲突原因，不强行选一个“唯一正典”。

## 谱系分析框架

不要以“神明等级表”作为跨文化比较的主轴。至少建立以下四个字段：

1. **宇宙秩序**：这个传统如何解释天地、时间、死亡、混沌、祖先、命运和社会秩序？
2. **传承媒介**：力量通过经文、歌舞、泥板、墓葬、神社、谱系、仪式、历法、航路、器物还是身体被保存？
3. **代理人关系**：神、祖先、英雄、祭司、国王、巫师、妖怪或职官如何和人谈判？谁有资格代表谁？
4. **边界技术**：进入、驱逐、净化、献祭、占卜、护送、封存、复归或跨世界的具体方法是什么？

补充记录：地域、时代、语言、性别与权力关系、活态信仰状态、版本差异、禁忌、现代再创作影响。中国神话尤其不能假设存在一条从盘古到玉皇的单一封闭神谱；要区分上古材料、先秦礼制、楚地巫觋、道教、佛教融合、地方庙祀、小说戏曲和现代创作。

## 影视改编流程

### A. 从神话事件提取戏剧发动机

把关系事件改写前，回答：

- 谁想得到什么，谁阻止他，谁为现状付出代价？
- 原故事中的亲缘、誓约、交换、惩罚、牺牲或变形，如何变成当代角色的不可逆选择？
- 神话中最有辨识度的动作、空间、物质和声音是什么？它们如何进入场面，而不是停留在旁白百科？
- 故事保留什么核心命题，改编什么叙事机制，明确舍弃什么过时或不适合本项目的部分？

至少产出：作者命题、主角欲望、对手压力、关系反转、关键场景、代价、结尾余波和可延展的下一层问题。

### B. 从神话实体建立角色

先区分“传统身份”和“本项目角色”：

- 传统身份：来源、版本、亲缘/敌对关系、权能、住所、器物、禁忌和故事功能。
- 项目角色：当下目标、秘密、恐惧、误判、关系对象、身体代价、视觉轮廓和行动选择。

不要把能力清单直接当人物性格；用能力制造选择压力。神祇要有秩序立场，英雄要有代价，怪物要有关系或规则，不只负责战斗。

### C. 从神话体系建立世界

每座神话世界至少写清：

- 本土人如何理解自己的世界，谁拥有解释权；
- 外来者为什么被允许或被迫进入；
- 本地时间、空间、身体、死亡和记忆如何运行；
- 仪式、禁忌、物品和地点怎样改变因果；
- 本土权威要什么，外来门徒解决不了什么；
- 这个世界在当前故事结束后会留下什么不可逆变化。

先选一个文化母体，再选择其内部版本；不要把多个传统的神名、圣物、服饰和法术拼成无来源的“全球神话大乱斗”。跨谱系合作必须有翻译媒介、权力不对等、明确代价和本土权威反应。

### D. 为视觉资产保留文化来源

调用电影图像 skill 时，为每个神话资产分别锁定：文化母体、时代/版本、形状母语、材料、动作/仪式、环境反应、色彩来源和禁用混搭。超自然显相要有重量、遮挡、声音、磨损和耗散，避免把所有神话变成统一的发光符文或游戏 CG。

## 输出格式

根据任务选择以下结构，不要每次都输出百科全书：

### 研究简报

`问题 → 数据集命中 → 来源核验 → 版本差异 → 可信度 → 尚未确定 → 对项目的可用结论`

### 神话改编卡

`文化母体/版本 → 核心命题 → 原始关系 → 当代戏剧发动机 → 主角选择 → 视觉动作 → 代价 → 改编边界 → 来源`

### 跨谱系比较

用表格比较四项秩序字段，不用“谁更强”作为结论；最后说明能否发生故事内翻译，以及翻译的代价。

### 剧本交接包

交给 `$craft-cinematic-screenplays`：一段准确的神话事实底稿、一段明确的项目改编、一条人物欲望线、一条因果线、关键场景和不可逆后果。不要把检索资料直接当成分场剧本。

## 质量与伦理护栏

- 不把数据集的数量、排名或“神话体系”标签解释成传统内部的权威等级。
- 不把后世小说、影视和游戏设定倒写成古代原典；看到版本混合要主动拆开。
- 不把活态宗教、族群身份、殖民时期分类或神圣仪式当作可随意消费的装饰。
- 不凭单一网络页面断言争议事实；给出来源、日期、地域和不确定性。
- 不为了“世界观统一”消除不同传统的时间尺度、身体观、性别结构和死亡观。
- 发现源数据中的模板化、重复、疑似幻觉或来源不足时，保留记录但标注风险，并建议核验，不静默修正成“事实”。

## 开源发布边界

- 默认数据已随 skill 放在 `references/world-mythology-dataset.md`，发布到 GitHub 前确认你拥有这份整理数据及其摘要、翻译和来源字段的再分发权。
- 如果数据来源、许可或第三方摘要不能公开，删除内置数据文件，改用 `--source PATH` 或 `MYTHOLOGY_SOURCE`，并在发布说明中提供数据来源和许可要求。
- 不把数据集统计数量当作传统内部的权威排名；公开版本更新时保留版本号、更新时间、来源变更和已知错误。
- skill 本身只依赖 Python 标准库，不联网、不上传用户数据；网络核验由调用它的模型按任务需要完成。
